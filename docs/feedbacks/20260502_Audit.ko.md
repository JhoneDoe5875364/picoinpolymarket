# PredictPix 피드백 — 제품 개선안 정리

**일자:** 2026-05-02  
**언어:** 한국어 ([English version](./20260502_Audit.md))

---

## 1. 마켓 리스트

### 1.1 현재 강점

- 카드 레이아웃이 깔끔함
- Yes / No 구분이 명확함
- 거래량·종료일이 잘 보임
- 상단 카테고리 배치

> 전체적인 룩이 마음에 든다. 색 변경도 괜찮고, 라이트·다크 모드 모두 대비가 충분하다.

마켓 리스트는 접근성이 좋아야 한다. 신규 사용자가 페이지에 들어와 몇 초 안에 다음을 이해할 수 있어야 한다.

- 무엇을 예측하는지,
- Yes가 무엇을 의미하는지,
- No가 무엇을 의미하는지,
- 마켓이 언제 끝나는지,
- 마켓이 얼마나 활발한지.

### 1.2 권장 추가 사항

- **[ADDED]** 다음 개선은 각 마켓 카드가 더 “살아 있는” 느낌이 나게 하는 것이다. 리스트는 단순 디렉터리가 아니라 활동·긴급도·신뢰감을 전달해야 한다.
- **[ADDED]** 해당 시 카드에 “Trending”, “New”, “Hot” 라벨을 직접 표시한다.
- **[ADDED]** “오늘 24건 거래”, “댓글 12개”, “곧 종료”, “거래량 +38%” 등 작은 활동 신호를 넣는다.
- **[ADDED]** 가능하면 컴팩트한 스파크라인 또는 미니 가격·히스토리 움직임 라인을 추가한다.
- **[ADDED]** Polymarket처럼 상단에 “Featured Market” 또는 회전하는 하이라이트 카드를 둔다.
- **[ADDED]** “곧 종료(Ending Soon)” 필터를 추가한다 — 긴급도가 참여를 높인다.
- **[ADDED]** 댓글이 생기면 “가장 많이 논의됨” 필터를 추가한다.

상단 카테고리는 유용하지만, 장기적으로는 정적인 필터보다 **탐색 경로**에 가깝게 동작해야 한다.

> **참고:** 사용하는 모든 이미지는 저작권 문제가 없는 것만 사용해야 한다.

### 1.3 제안 카테고리 구조

- Trending
- New
- Hot
- Ending Soon
- Sports
- Crypto
- Politics / Public Events
- Entertainment
- Community

### 1.4 라벨 정의 제안

| 라벨 | 정의 |
|------|------|
| **New** | 최근 48~72시간 이내 생성 |
| **Trending** | 직전 기준 대비 최근 24시간 거래·댓글 활동이 높음 |
| **Hot** | 높은 거래량·거래 건수·댓글 활동·최근 가격 움직임의 조합 |
| **Ending Soon** | 향후 24~72시간 이내 마켓 종료 |

- **[ADDED]** “Trending”은 **누적 거래량**이 아니라 **최근 활동** 기준이어야 한다. 최근 1시간에 10건 거래된 마켓이, 오래된 대량 거래만 있고 최근 활동이 없는 마켓보다 더 “뜨거워” 보여야 한다.

## 2. 마켓 규칙 / 맥락 영역

규칙·맥락 영역은 더 눈에 띄고, 소화하기 쉬우며, **마켓마다 구체적**이어야 한다. 규칙은 단순 정보가 아니라 **신뢰 레이어**다. 사용자는 Pi를 보내기 전에 무엇을 예측하는지 정확히 알아야 한다.

### 2.1 권장 구조

- **마켓 질문** — 일상 언어로 된 마켋 (예: “2026년 6월 30일까지 팀 X가 우승할까?”)
- **Yes로 인정되는 경우** — Yes 정산 기준을 명확히
- **No로 인정되는 경우** — No 정산 기준을 명확히
- **정산 출처** — 최종 결과의 근거 (공식 리그 사이트, 공개 블록체인 데이터, 검증된 뉴스, 정부 공식, 나열된 출처를 사용한 플랫폼 관리자 판단 등)
- **정산 시점** — 정산 예정일 또는 조건
- **엣지 케이스** — 행사 취소·연기·모호·미해결 시 처리 요약

### 2.2 규칙 UX 추가

- **[ADDED]** 이 영역은 거래 액션 영역과 **시각적으로 분리**한다. 사용자가 정산 조건을 쉽게 볼 수 없는 상태에서 예측을 넣게 해서는 안 된다.
- **[ADDED]** 신뢰를 위해 모든 마켓에 동일 구조의 “Resolution Rules” 카드: 질문, Yes 기준, No 기준, 출처, 마감 시각, 정산 시각, 엣지 케이스.
- **[ADDED]** 짧은 “왜 중요한지” 또는 “마켓 맥락” 문단은 가능하되 **중립적**으로 유지한다. Yes/No로 밀어붙이는 표현은 피한다.

## 3. 거래 패널

### 3.1 현재 강점

- 가격이 명확함
- 수수료 투명
- 잠재 수익 표시
- 신규 사용자도 이해하기 쉬움

구조적으로 견고하며, 처음 온 사용자도 쓰기 쉽다.

### 3.2 개선 필요

가장 큰 개선은 **상호작용 이후의 느낌**이다.

- 비용·지급액·순결과 구분을 더 명확히
- 거래 후 피드백
- 예측 제출 후 확인·상태 변화
- **정확하고 일관된 계산** — 신뢰에 결정적이다.

### 3.3 용어

- **[ADDED]** “potential profit” 등은 규제상 나중에 바꿀 수 있다. 대안: “Possible return”, “Estimated result”, “If correct, you may receive”, “Projected payout”, “Outcome estimate” 등.
- **[ADDED]** “cost”, “payout”, “profit”, “return”을 섞어 쓰지 말 것. 앱 전체에서 각 용어는 **하나의 의미**만 갖게 한다.

**제안 용어**

| 용어 | 의미 |
|------|------|
| **Amount** | 예측에 걸 Pi |
| **Fee** | 플랫폼 수수료 |
| **Total Cost** | 금액 + 수수료 |
| **Estimated Return** | 맞았을 때 받을 수 있는 금액 |
| **Net Result** | 예상 반환 − 총 비용 |
| **Loss if Incorrect** | 총 비용(틀렸을 때) |

### 3.4 확인 전 계산 내역

- **[ADDED]** 확인 전에 계산 내역을 명확히 보여준다. 예: 예측 금액 10 Pi / 수수료 0.2 Pi / 총 비용 10.2 Pi / 맞을 시 예상 반환 18.4 Pi / 비용 차감 순결과 8.2 Pi / 틀릴 시 반환 0 Pi
- **[ADDED]** 마켓 카드·거래 패널·프로필·관리자 화면 간 계산이 조금이라도 어긋나면 신뢰가 즉시 무너진다.

### 3.5 거래 확인

제출 후 앱이 그냥 리셋되거나 넘어가면 안 된다.

- **[ADDED]** 완료마다 확인 상태: “예측이 성공적으로 제출되었습니다.” 이후 마켓명, Yes/No, 보낸 금액, 수수료, 트랜잭션/참조 ID, 지갑·결제 상태, 예상 정산일, 프로필에서 포지션 보기 링크.
- **[ADDED]** Pi 결제 확인 중 로딩 상태. 클릭이 먹혔는지 의심하게 하지 말 것. 예: 결제 준비 → Pi 확인 대기 → 결제 감지 → 포지션 기록 → 예측 확정.
- **[ADDED]** 실패 상태와 복구 안내: 결제 취소 / 대기 / 결제는 됐으나 포지션 미기록 / 포지션은 됐으나 확인 지연 / 네트워크 오류. Pi 브라우저·지갑 플로우에 특히 중요하다.

## 4. 댓글 영역

거래 패널 또는 마켓 페이지에 댓글을 두는 방향에 관심이 있다. 나중에 추가해도 되지만 참여에는 중요할 수 있다.

- **[ADDED]** 전체 댓글을 거래 패널 **안**에 넣지 않는다. 패널은 액션에 집중. 마켓 상세 아래에 “Discussion”을 두고, 패널 근처에는 댓글 수만 보이게 한다.

### 4.1 권장 레이아웃

1. 상단: 마켓 질문  
2. 차트 / 활동 / 맥락  
3. 거래 패널 (데스크톱 오른쪽, 모바일은 아래)  
4. 규칙 카드  
5. 토론 섹션  
6. 관련 마켓  

### 4.2 댓글 통제 (첫날부터)

- 댓글 신고
- 관리자 숨김/삭제
- 사용자 뮤트/밴
- 관리자 고정 설명
- 관리자 “공식 정산 안내”
- **[ADDED]** 사용자 댓글과 별도로 “Admin Note” 또는 “Market Clarification” 기능 — 정산 전 설명이 필요할 때 신뢰를 지킨다.

## 5. 관리자 패널

### 5.1 현재 강점

- 마켓 관리
- 제안 파이프라인
- 사용자 통제
- 지표

> 데이터가 전부이므로, 관리 페이지에서 무슨 일이 일어나는지 한눈에 보이게 캡처할수록 좋다.

- **[ADDED]** 관리자 패널은 마켓 관리만이 아니라 **리스크·신뢰·결제·사용자 행동 패턴**을 잡는 데 도움이 되어야 한다. **안전 센터**로 발전시킨다.

### 5.2 권장 관리자 지표

**마켓 지표**

- 총 거래량, Yes/No 거래량
- 고유 사용자 수, 예측 건수
- 평균 예측 규모, 최대 예측
- 마감일, 정산 상태
- 미해결 마켓, 분쟁·댓글이 많은 마켓

**사용자 지표**

- 총 사용자, 일/주/월 활성
- 열린 포지션·해결된 포지션 보유 사용자
- 재방문 사용자, 활동 상위 사용자
- 결제 실패/대기 사용자, 플래그 사용자

**결제·지갑 지표**

- 사용자→앱 입금, 앱→사용자 출금
- 대기·실패 출금, 수동 출금 대기열
- 지갑 연결/미연결
- 결제 불일치 경고

**신뢰·안전 지표**

- 분쟁 마켓, 댓글 활발한 마켓
- 의심 활동, 중복 사용자
- 급격한 대량 거래, 미해결 엣지 케이스
- 관리자 수동 개입

### 5.3 관리자 추가 기능

- **[ADDED]** 자동화가 덜 되어도 “Payout Queue”를 둔다: 사용자, 마켓, 결과, 지급액, 지갑 주소, 결제 상태, 트랜잭션 ID, 관리자 액션.
- **[ADDED]** **감사 로그(audit log)** — 마켓 생성/수정/정산, 출금 생성·지급 완료 처리, 사용자 밴, 댓글 삭제, 규칙 변경 등 중요한 관리 액션을 모두 기록한다.

## 6. 프로필 대시보드

### 6.1 현재 강점

- 포지션 테이블
- 손익 가시성
- 필터
- 과거 데이터

사용자가 자신의 행동이 정확히 기록됐다고 믿게 해야 한다.

- **[ADDED]** 내부 입출금 지갑 제품을 피하려면 프로필은 “계정 잔액”보다 **“예측 이력”** 중심이 낫다.

### 6.2 권장 프로필 섹션

**진행 중인 예측:** 마켓, Yes/No, 금액, 수수료, 총 비용, 예상 반환, 마감일, 상태  

**종료된 예측:** 마켓, 선택 쪽, 결과, 걸었던 금액, 반환액, 순결과, 트랜잭션 참조, 정산 출처  

**결제 이력:** 보낸 Pi, 돌려받은 Pi, 트랜잭션 ID, 대기/완료/실패  

**지갑:** 연결된 Pi 사용자명·지갑 참조, 출금 목적지, 마지막 검증일  

- **[ADDED]** 법무 검토 없이 “내부 잔액”을 보여주지 않는다. 내부 잔액은 수탁/에스크로 느낌을 강하게 한다. **거래 이력 모델**이 비수탁 목표와 더 잘 맞는다.

## 7. 비수탁(Non-Escrow) Pi 플로우

규제·수탁 리스크를 줄이기 위해 비수탁으로 가고자 한다. 선호 모델: 사용자가 예측 → Pi 전송 → 마켓 정산 → Pi는 **내부 지갑 잔액이 아니라** 사용자 지갑으로 돌아간다.

> 이 방향이 맞다고 본다.

입금/출금 시스템은 마찰·책임·거래소·카지노 지갑·수탁 플랫폼과의 **규제적 유사성**을 높인다. 사용자에게 보이는 잔액을 최소화하는 편이 제품·신뢰 면에서 깔끔하다.

- **[ADDED]** 단기 최선은 “입출금”이 아니라 **“예측마다 결제, 맞으면 직접 출금”**이다.

### 7.1 제안 플로우

1. 마켓 선택 → Yes/No → 금액 입력  
2. 앱이 정확한 비용·수수료·예상 반환 표시  
3. 사용자가 Pi 결제 확인  
4. 결제 검증 → 포지션 생성  
5. 마켓 정산 후, 맞으면 사용자 지갑으로 직접 지급  
6. 프로필에 전체 거래 이력  

### 7.2 법·표현 주의

- **[ADDED]** 이것만으로 모든 규제 리스크가 사라지지는 않는다. 관할에 따라 이벤트 베팅·예측 마켓 거래·이진 계약 등으로 볼 수 있다. 그래도 **저장 가치 지갑**을 앱 안에 만드는 것보다 내부 잔액 없이 가는 편이 낫다.
- **[ADDED]** 법무 검토 전까지 deposit, withdraw, account balance, investment, trading profit, guaranteed return, cash out, portfolio 등 표현은 피한다.

**상대적으로 안전한 표현:** prediction amount, send Pi, return, resolved result, payment history, payout status, estimated outcome, activity history  

**피해야 할 표현:** deposit, withdraw, balance, profit, investment, trading, bankroll, cash out, yield

## 8. 전체 제품 느낌

Trending, New, Hot 아래에 더 역동적인 마켓을 보고 싶다. 정적인 리스트만 보이면 안 된다 — **활동 신호**가 필요하다.

Polymarket 상단 회전 카드처럼 특정 마켓을 강조하고 움직임·그래프를 보여주는 방식이 좋았다. 그대로 복제할지는 모르겠지만, **움직이고 활발한 느낌**을 주는 아이디어는 좋다.

- **[ADDED]** 유동성이 아직 낮아도 PredictPix는 **살아 있는 느낌**이 나야 한다. 신규 예측 플랫폼에 매우 중요하다.

### 8.1 조작 없이 활동감을 내는 방법

- Featured 캐러셀, 최근 생성·최근 정산 마켓
- 가장 많이 논의된 마켓, 오늘 가장 큰 움직임, 곧 종료
- 새 제안 제출, 관리자 오늘의 픽
- 커뮤니티 폴/프롬프트, 워치리스트, “이 마켓 공유” CTA

- **[ADDED]** 가짜 거래량·가짜 활동은 금지. 다만 **실제 활동**을 더 흥미롭게 보여주는 것은 권장한다.

## 9. 우선순위 개선

### 우선순위 1 — 신뢰·계산 정확성 (가장 중요)

- 정확한 비용·수수료·예상 반환·순결과, 용어 일관성
- 트랜잭션 확인, 결제 상태, 오류 상태, 프로필 기록

### 우선순위 2 — 마켓 규칙·정산 명확성

- Yes/No 의미, 진실 출처, 정산일, 엣지 케이스, 관리자 설명

### 우선순위 3 — 거래 후 경험

- 결제 시작·완료, 포지션 생성, 포지션 보기, 대기·실패, 정산 후 지급 상태

### 우선순위 4 — 역동적 탐색

- Trending / New / Hot / Ending soon, Featured, 움직임 지표, 댓글 수, 활동 신호

### 우선순위 5 — 관리 통제·감사 추적

- 출금 대기열, 감사 로그, 정산 노트, 실패 결제 추적, 사용자 리스크 플래그, 분쟁 마켓, 수동 개입 이력

## 10. 최종 권고

PredictPix는 올바른 방향으로 가고 있다. 시각 구조, 마켓 리스트, 거래 패널, 관리자 개념, 대시보드 방향에 대한 피드백은 긍정적이다.

다음 도약은 기능만 늘리는 것이 아니라, 플랫폼이 **신뢰할 수 있고, 정확하고, 살아 있으며, 투명하고, 안전하게 느껴지게** 만드는 것이다.

### 세 가지 핵심 원칙

1. **Pi/돈에 대한 모호함 없음** — 보내는 금액, 수수료, 받을 수 있는 금액, 틀렸을 때 결과를 항상 알 수 있어야 한다.  
2. **마켓 결과에 대한 모호함 없음** — 참여 전에 정산 규칙이 분명해야 한다.  
3. **죽은 화면 없음** — 마켓 페이지·리스트·대시보드에 활동·움직임·토론·상태를 가능한 한 보여준다.  

- **[ADDED]** 가장 강하게 권하는 것은 **비수탁·거래 이력 모델**로 다음 버전을 짓는 것: 예측마다 Pi 전송, 포지션 기록, 정산 후 지갑으로 직접 지급. 법무에서 안전하다고 할 때까지 내부 잔액은 피한다. 제품이 더 단순하고 설명하기 쉽다.
